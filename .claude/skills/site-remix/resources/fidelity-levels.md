# 변형 수준 (Fidelity Levels)

> `site-remix` P3(변형 수준 질문) · P4(치환 매핑) · P5(기획 문서 연결)에서 쓰는 단일 기준.
> 이름·정의·레이어 허용 범위는 `design-spec.md` 3장을 그대로 옮긴 것이다. 절 번호는 `project-planning/resources/doc-templates.md`를 가리키며 본문을 복제하지 않는다.

## 1. 수준 정의

| 수준 | 이름 | 한 줄 정의 |
|---|---|---|
| L1 | 미러 (100%) | 구조·리듬·인터랙션 문법을 그대로 두고 기획과 브랜드만 갈아 끼운다 |
| L2 | 변주 (약간의 변주) | 뼈대는 같고 섹션 일부와 섹션 내부 배치를 새 기획에 맞게 조정한다 |
| L3 | 변형 (구조 변형 응용) | 원본은 패턴 어휘로만 쓰고 IA와 섹션 구성을 새 기획이 주도해 다시 짠다 |

## 2. 레이어별 허용 범위

| 레이어 | L1 미러 | L2 변주 | L3 변형 |
|---|---|---|---|
| IA (페이지 수·경로 구조) | 동일 | 동일 | 새 과업 기준 재편 |
| 섹션 순서·개수 | 동일 | 순서 유지, 가감·교체 합계가 원본 섹션 수의 25% 이하(최소 1개 허용), 인접 교환 1회 | 자유. 원본 섹션마다 처리와 근거를 매핑표에 기록 |
| 섹션 내부 레이아웃 | 같은 아키타입·같은 열 수·같은 비율 | 같은 아키타입 계열(layoutTaxonomy 같은 카테고리) 안에서 비율·정렬·반복 수 변주 | layoutTaxonomy에서 새 아키타입 선택 가능 |
| 토큰 구조 (역할 수, 타입 스케일 비, 간격 리듬, radius·elevation 언어) | 승계 | 승계 | 새 브랜드 무드 기준으로 재결정 |
| 토큰 값 (색, 서체, 구체 수치) | 새 브랜드 | 새 브랜드 | 새 브랜드 |
| 인터랙션 패턴 | 동일 문법 | 유지, 1~2개 교체 | 02 4절 원칙에서 재도출 |
| 기획 (목적·사용자·대상·과업) | 새 기획. 원본 슬롯에 1:1로 채운다 | 새 기획. 안 맞는 슬롯은 조정 | 새 기획이 구조를 주도 |
| 브랜드 (이름·로고·카피·이미지·영상) | 전부 교체 | 전부 교체 | 전부 교체 |

## 3. 불변 규칙 (모든 수준)

- 항상 교체: 브랜드 이름, 로고, 카피 문장, 이미지·영상·커스텀 아이콘, 색 값, 서체, 메타 정보.
- 절대 가져오지 않음: 원본의 소스 코드, 에셋 파일·에셋 URL(핫링크 포함), 카피 문장, 트래킹 스크립트.
- 가져오는 것은 측정값과 패턴뿐: 섹션 역할과 순서, 아키타입, 열 수·비율, 타입 스케일 비, 간격 리듬, 밀도, 구분 언어(선·면·여백), 인터랙션 문법.
- L1에서 새 기획에 채울 내용이 없는 슬롯은 지우지 않고 `(미정, Qn)` + 질문으로 남긴다. 지우려면 L2로 올린다.
- 원본 브랜드 이름은 청사진 부록과 03 4.1절 레퍼런스 행에만 쓴다.

## 4. P3: 변형 수준 질문 방법

1. 청사진 요약을 먼저 보여준다: 페이지 수, 페이지별 섹션 수, 눈에 띄는 인터랙션 2~3개(청사진 2절·3절에서 뽑는다).
2. L1·L2·L3를 선택지로 제시한다. 각 선택지에 "이 사이트라면 무엇이 남고 무엇이 바뀌는지" 한 줄을 붙인다.
   - 예: "L1: 6개 섹션 순서·비율 그대로, 카피와 색만 바뀝니다."
   - 예: "L2: 6개 섹션 중 1~2개를 새 기획에 맞게 바꾸거나 뺄 수 있습니다."
   - 예: "L3: 섹션 구성을 새 기획이 주도해서 다시 짭니다. 원본은 참고 어휘로만 남습니다."
3. 페이지마다 다른 수준을 원하면 페이지 단위 지정을 허용한다. 이 경우 청사진 6절 매핑표에 페이지별로 수준을 적는다(예: `L1` / `L2` 열을 페이지 행마다 표기).
4. 질문 도구: Claude는 AskUserQuestion으로 L1·L2·L3(+ 페이지별 지정) 선택지를 준다. Codex는 번호 목록(1. L1, 2. L2, 3. L3, 4. 페이지별로 다르게)으로 묻는다.
5. P0에서 이미 수준을 들었으면 P3를 건너뛴다(design-spec 2장 질문 규칙).

## 5. P4: 치환 매핑표 (청사진 6절)

### 5.1 표 형식

열: `# / 원본 슬롯 역할 / 새 기획 대응물 / 처리 / 근거`. 근거 칸은 01 5절 과업 번호를 쓴다.

| # | 원본 슬롯 역할 | 새 기획 대응물 | 처리 | 근거 |
|---|---|---|---|---|
| 1 | hero | 브랜드 선언 히어로 | 유지 | 1 |
| 2 | logo-cloud | (미정, Q1) | 유지 | - |

### 5.2 처리 값

| 값 | 뜻 |
|---|---|
| 유지 | 원본 슬롯의 역할·아키타입을 그대로 두고 내용만 새 기획으로 채운다 |
| 변주 | 같은 아키타입 계열 안에서 비율·정렬·반복 수만 바꾼다 |
| 교체 | 슬롯 위치는 유지하되 역할(고정 어휘)을 다른 것으로 바꾼다 |
| 삭제 | 슬롯을 없앤다 |
| 신규 | 원본에 없던 슬롯을 새로 더한다 |

수준별 허용 여부:

| 처리 | L1 | L2 | L3 |
|---|---|---|---|
| 유지 | 가능 | 가능 | 가능 |
| 변주 | 불가(같은 비율까지만) | 가능 | 가능 |
| 교체 | 불가 | 예산 안에서 가능 | 가능 |
| 삭제 | 불가 | 예산 안에서 가능 | 가능 |
| 신규 | 불가 | 예산 안에서 가능 | 가능 |

### 5.3 L2 변경 예산

- 교체·삭제·신규의 합계가 원본 섹션 수의 25% 이하(소수는 올림, 최소 1개 허용). 인접 교환은 1회까지 별도로 허용.
- 예시: 원본 8섹션이면 25%는 2개. 원본 4섹션이면 25%는 1개(올림).
- 매핑표 아래에 계산 한 줄을 남긴다: `변경 예산: 원본 8섹션 × 25% = 2개, 교체 1 + 신규 1 = 2개 사용`.
- 예산을 넘으면 그 자리에서 확정하지 않는다. "L3로 올릴지" 사용자에게 묻고 답을 받은 뒤 계속한다.

### 5.4 L1 빈 슬롯

L1에서 새 기획에 채울 대응물이 없으면 새 기획 대응물 칸에 `(미정, Qn)`을 쓰고 같은 질문을 결정 현황 비고에 남긴다. 슬롯 자체를 지우지 않는다. 지우려면 사용자에게 L2로 올릴지 먼저 묻는다.

### 5.5 슬롯 채우기 원칙

- 슬롯에서 물려받는 것은 역할과 분량 신호뿐이다: 제목 길이급(짧은/긴 헤드라인), 문단 수, 반복 항목 수, 미디어 비율.
- 슬롯에 채우는 내용(카피, 이미지 방향, 구체 문구)은 전부 새 브리프에서 새로 쓴다.
- 카피는 새로 쓴다. 원본 문장의 번역, 의역, 문장 구조 모방을 하지 않는다. 원본 카피는 참고 자료로만 청사진 3절에 존재하고 02·03·src로 넘어가지 않는다.

## 6. P5: 기획 문서 연결

### 6.1 수준별 연결 표

| 문서·절 | 재료 출처 | 수준별 규칙 |
|---|---|---|
| 01 전체 | 새 브랜드·기획 브리프 (원본 카피·원본 기획 아님) | 전 수준 동일. 01 금지 목록 그대로 적용 |
| 01 5절 과업 | 브리프 + 청사진 4절(원본의 추정 과업 구조)을 개수·유형 점검표로만 | L1: 원본 흐름 수와 1:1이 되게 과업을 세운다. L2: 1:1 기본, 조정 허용. L3: 브리프 주도 |
| 02 2.1절 페이지 리스트 | 청사진 1절 사이트 맵 | L1·L2: 같은 페이지 구성. L3: 재편 |
| 02 2.2절 계층 트리 | 청사진 6절 치환 매핑 결과 | 섹션 이름은 새 기획의 역할 이름으로 다시 짓는다(원본 문구 금지) |
| 02 4절 인터랙션 원칙 | 01 3절 가치가 근거. 청사진 3절 인터랙션 관찰에서 고른다 | L1: 관찰된 패턴을 전부 원칙으로 설명. L3: 재도출 |
| 02 5절 컴포넌트 리스트 | 청사진 5절 모듈 분해 + `component-work/resources/components.md` 재활용 확인 | 카테고리 칸에 `templates`, `sections` 등 폴더명. 템플릿·섹션도 행으로 적는다 |
| 03 1절 무드 | 01 3.2절 (새 브랜드) | 원본 무드를 옮기지 않는다 |
| 03 2절 레이아웃 전략 | 청사진 2절의 아키타입 id·콘텐츠 신호 | L1·L2: 관찰값 승계. L3: 재선택. id는 `layoutTaxonomyData.js`에 있는 것만 |
| 03 3절 토큰 방향 | 구조는 청사진 3절 관찰, 값은 새 브랜드 | 3.1~3.3 근거 칸은 01 3절·02 4절 이름. 관찰값은 근거가 될 수 없다(비고로만) |
| 03 4.1절 레퍼런스 | 사용자가 준 URL이 REF-01 | 참고 포인트: 구조·리듬·밀도. 잠금: L1 예 / L2 부분 / L3 아니오 |
| 03 4절·4.2절 에셋 방향 | 청사진 3절 미디어 인벤토리(역할·비율·개수)로 FORMAT만. LOOK·SUBJECT는 새 브랜드 | 원본 이미지를 레퍼런스 이미지로 쓰지 않는다 |
| 03 5절 변경 토큰 요약 | `component-work/resources/mui-theme.md` 현재값 → 새 값 | `.claude/rules/design-system.md` 3절 "토큰을 바꾸는 순서" 준수 |

### 6.2 문서별 주의

- **01**: 브리프에서만 채운다. `doc-templates.md` 1장의 금지 목록(화면·페이지 이름, 컴포넌트명, 색상값·서체명·px, 레이아웃 패턴, 전환·연출, 구현 상태, 라이브러리 선택)이 그대로 적용된다. 원본에서 본 것이라도 이 목록에 걸리면 01에 쓰지 않는다.
- **02 2.2절**: 트리의 섹션 이름은 새 역할 이름이다. 청사진 6절 매핑표의 "새 기획 대응물" 칸 이름과 글자가 같아야 한다. 원본 문구(예: 원본 사이트의 섹션 헤딩)를 그대로 쓰지 않는다.
- **03 3절**: 3.1~3.3절의 근거 칸은 01 3절 가치나 02 4절 원칙의 이름만 올 수 있다(`doc-templates.md` 0.3절 근거 규칙과 동일). 청사진에서 관찰한 값(원본의 색·서체·수치)은 근거가 될 수 없고, 참고했다는 사실은 비고 목록으로만 남긴다.
- **03 4.1절**: REF-01 행은 사용자가 준 원본 URL이다. 파일/URL 칸에 그 URL을 쓰고, 참고 포인트 칸에는 구조·리듬·밀도 같은 패턴 단어만 쓴다(카피·색·이미지는 참고 포인트에 쓰지 않는다). 잠금 칸은 수준을 그대로 옮긴다: L1은 `예`, L2는 `부분`, L3는 `아니오`.
- **결정 현황 비고**: 각 절의 비고 칸에 수준 표기를 20자 이내로 남긴다. 예: `L1 구조 승계`, `L2 2섹션 교체`, `L3 재구성`.

### 6.3 역류

P5 도중 변형 수준을 바꾸면 순서는 이렇다:

1. 청사진 6절 매핑표를 먼저 고친다(처리 값과 예산 재계산).
2. 02 2.2절, 02 5절을 잠정으로 내리고 바뀐 부분을 다시 쓴다.
3. 03 2절을 잠정으로 내리고 레이아웃 전략을 다시 맞춘다.
4. 상태 갱신 후 사용자에게 무엇이 잠정으로 내려갔는지 알린다(`doc-templates.md` 0.2절 "상류 변경" 절차와 동일).

## 7. 저장 전 점검 목록

문서를 저장하기 전에 아래를 확인한다.

- `doc-templates.md` 5장의 정합성 점검(01~03 이름 대조, 개수·번호 대조, 근거 칸 등)을 그대로 수행했는가.
- 매핑표의 처리 값이 선택한 수준에서 허용되는가(5.2절 표 대조).
- L2라면 변경 예산 계산 줄이 매핑표 아래에 있는가.
- L1의 빈 슬롯이 지워지지 않고 `(미정, Qn)`으로 남았는가.

권리 점검(3장 불변 규칙 위반 여부):

```
grep -rn "원본 브랜드명" docs/{project}/01-project-summary.md docs/{project}/02-ux-flow.md docs/{project}/03-visual-direction.md src/
grep -rEn "https?://" docs/{project}/01-project-summary.md docs/{project}/02-ux-flow.md docs/{project}/03-visual-direction.md src/data/{project}
grep -rn "{원본 카피 문장 일부}" docs/{project}/ src/
```

- 첫 줄: 원본 브랜드명이 03 4.1절 레퍼런스 행과 청사진 부록 밖에 나타나지 않는지.
- 둘째 줄: 에셋 URL(핫링크)이 데이터 파일에 남지 않았는지. 03 4.1절 REF-01의 사용자 제공 URL 한 줄은 예외다.
- 셋째 줄: 원본 캡처 요약(`reference/summary.md`)에서 눈에 띈 카피 문장을 그대로 검색해 01~03과 `src/data/{project}/content.js`에 없는지 확인한다.
